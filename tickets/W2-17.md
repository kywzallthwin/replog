## Goal
Let a user rename an exercise they created, from the pencil action in the Add Exercise picker,
without corrupting historical workouts.

## Scope
- Add an owner-only update contract for custom exercises that changes the name, the category, or
  both in one request. Global catalog exercises remain immutable.
- Enforce normalized-name uniqueness across the global catalog and the owner's own custom
  exercises, rejecting duplicates consistently on create and update.
- Extend the existing pencil editor in the exercise picker with a name field alongside the
  category control, saved together with one Save action.
- Preserve existing `SessionExercise.nameSnapshot` values and completed workout rendering.
- Provide accessible pending, error, and focus-restoration behavior for the editor.

## Out of scope
- Deleting exercises, the archival `archivedAt` field, and the transactional program-day cleanup
  from W2-06.
- Renaming global catalog exercises, merging exercises, or rewriting historical snapshots.
- Exposing the pencil action on "In use" rows.
- Production database changes, deployment, or provider configuration.

## Acceptance criteria
- Owners can rename only their own custom exercises; built-in exercises expose no rename action.
- The pencil opens a combined name and category editor with the current name pre-filled, and the
  name field receives focus.
- Saving sends only the changed fields in a single request.
- Duplicate normalized names are rejected on update with the same message used on create, and the
  error is shown without discarding the typed name.
- Save is disabled when the trimmed name is empty or when neither field changed.
- Escape cancels the editor and restores focus to the pencil without closing the picker.
- Another user cannot view or edit the custom exercise; the request returns 404.
- Completed workout history keeps the name that was logged; the catalog, program editor, and
  progress page show the new name.
- The flow fits 375px and keeps 44px touch targets.

## Risks And Rollback
- Risk: renaming mutates a name other features resolve by exact value. The seed and starter
  program lookups resolve global exercises by name with `ownerId: null`, so an owner-owned custom
  exercise rename cannot affect them.
- Risk: duplicate names. The same `normalizeExerciseName` rule used on create is applied on
  update, excluding the exercise being edited.
- Rollback: revert the route and the client change. Rows already renamed keep their new names;
  there is no schema change to unwind.

## Stop conditions
- Do not commit, push, deploy, or apply production changes without explicit user authorization.
- Stop if the work requires editing the global catalog, rewriting historical snapshots, or
  expanding into W2-06's deletion and archival semantics.

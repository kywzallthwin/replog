# AV-01: Free Hosting Startup Reliability

State: done — probed and verified on 2026-11-02

## Goal
Diagnose free-host cold-start failures, report sanitized evidence, and make startup recover automatically without replaying dispatched workout mutations.

## Scope
- Record deployed Worker version, Render revision, and effective upstream configuration; measure direct Render `/health` and proxied `/ready` during genuine idle wake-ups.
- Add sanitized readiness and Worker upstream diagnostics (request ID, duration, status, failure category only).
- Keep `/health` independent of Neon and preserve `/ready` response compatibility while reporting database readiness errors internally.
- Fix only defects confirmed by diagnostics; classify provider failures that occur before Express.
- Improve startup progress/deadline/recovery UI and share/cancel readiness work safely.
- Verify authentication distinction, exactly-once workout writes, mobile layout, and recovery scenarios.

## Out of scope
- Paid hosting, backend/database migration, offline sync, credential changes, public URL changes, and unrelated workout feature changes.
- Cloudflare/Render/DNS/secrets changes or deployment until independent review, rollback records, and explicit deployment authorization are complete.
- Commit, push, or deploy.

## Acceptance criteria
- `/health` does not access the database; `/ready` retains `{ok:true}` and `{ok:false,code:"API_STARTING"}` compatibility and logs sanitized DB failures.
- Worker/readiness diagnostics contain request ID, duration, status, and category; never credentials, cookies, database URLs, secrets, or request bodies.
- Startup shows elapsed time and progress; after 90 seconds offers a recoverable unavailable view, retries every 15 seconds only while visible/online, and recovers immediately on reconnection or manual retry.
- Readiness sequences are shared and abandoned checks canceled; retry overlap is prevented; dispatched mutations are never replayed.
- Repeated 504, readiness failure, timeout/deadline, manual/automatic recovery, cancellation, offline/reconnect, React Strict Mode, auth distinction, exactly-once writes, and 375px layout are verified.
- Genuine idle wake-up timings/statuses, provider revisions/configuration, correlated logs, independent security/deployment review, and rollback revisions are recorded before any deployment. Post-deploy checks cover login/workout save after >15 minutes and a longer idle interval.

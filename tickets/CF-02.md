# CF-02: Render API Mode and Edge Security

**State:** proposed  
**Implementer:** Server agent  
**Reviewer:** Authentication/security agent

## Goal

Prepare Express for CF-01 while retaining the Render frontend as a rollback option.

## Scope

Bound readiness; add API/static switches; support exact transitional origins; authenticate Worker requests; preserve client-IP rate limiting; extend server tests and Render configuration.

## Owned Files

`server/src/env.ts`, `server/src/index.ts`, `server/src/security.ts`, new readiness/edge helpers, auth rate-limit setup, relevant server tests, `server/.env.example`, and `render.yaml`. Do not edit Worker/client code, `STATUS.md`, or other tickets.

## Implementation

- Add a five-second database readiness helper. Keep `/health` dependency-free and `/ready` database-backed.
- Set no-store headers on `/api`, `/ready`, and `/health`.
- Strictly validate `SERVE_CLIENT`, `REQUIRE_EDGE_PROXY`, `ADDITIONAL_CLIENT_ORIGINS`, and `EDGE_PROXY_SECRET`.
- Parse comma-separated exact origins; require HTTPS in production and reject wildcards, paths, credentials, queries, and fragments.
- Keep `CLIENT_URL` canonical for OAuth and reset links; allow canonical, transitional, and safe development origins in CORS/CSRF checks.
- Compare the edge secret in constant time. When enforcement is enabled, require it on `/api`, `/api/*`, and `/ready`; keep `/health` public.
- Trust `CF-Connecting-IP` for rate limits only after edge validation; otherwise use Render-derived `req.ip`.
- Keep `app.set("trust proxy", 1)`.
- Drive static serving from `SERVE_CLIENT`, preserving the `createApp({serveClient})` test override.
- Preserve cookie/JWT behavior, the one-service Blueprint, and the Render client build during rollback.

## Verification

Test readiness bounds, no-store headers, environment/origin validation, edge-secret enforcement, trusted IP/rate-limit behavior, cookie parity, OAuth/reset URLs, both static modes, and API JSON `404`s.

## Acceptance Criteria

- `/ready` is bounded and `/health` satisfies Render.
- Direct API access is rejected after enforcement.
- Direct clients cannot spoof trusted IPs.
- CORS/CSRF accept only exact configured origins.
- Cookies and JWT behavior remain unchanged.
- Render frontend rollback remains configurable.

## Stop Conditions

Stop if a schema migration or wildcard origin is needed, health checks break, arbitrary proxy trust is required, or cookie security must weaken.

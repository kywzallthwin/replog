# W2-03: Persistent Rest-Timer Controls

State: proposed

## Goal
Make the 90-second rest timer an always-available, durable control during active workouts.

## Scope
- Keep the rest-timer panel visible during an active workout, including its idle state.
- Provide Start/restart, +15 seconds, and Skip controls with a clear running and expired state.
- Start or restart the timer only after a successful set create or update.
- Persist an absolute expiry per session so refreshes, backgrounding, and remounts do not reset elapsed time.
- Clear timer state when the workout is finished or cancelled.
- Keep the control visible while scrolling without covering workout actions or the mobile navigation.

## Out of scope
- Server-synced timers, notifications, sounds, vibration, and user-configurable default durations.
- Timers outside an active workout.

## Acceptance criteria
- An active workout always exposes a 1:30 rest-timer control before the first set is logged.
- Successful set saves restart the countdown; failed saves do not.
- +15 seconds extends a running timer or resumes from zero, and Skip returns it to the idle state.
- Refreshing or backgrounding preserves the correct remaining time for that session only.
- Controls are keyboard accessible, have 44px targets, and remain usable at 375px.

## Verification
- Focused timer-hook and workout-page tests with fake timers.
- `npm run check`.
- Manual 375px checks for idle, running, expired, refreshed, backgrounded, finished, and cancelled states.

## Stop conditions
- Do not add platform notifications, audio, haptics, or rest-duration preferences.

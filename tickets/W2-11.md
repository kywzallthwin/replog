# W2-11: Wave 2 Integration And Mobile Acceptance Gate

State: proposed

## Goal
Verify the completed Wave 2 feature set as one coherent mobile-first user journey and close the wave without carrying regressions forward.

## Dependencies
- W2-01 through W2-10 must be `done` before this ticket begins.

## Scope
- Add or update a browser journey covering notes, previous references, rest timing, both reorder flows, custom exercise lifecycle, unit preference, progress chart/guide, and completed workout deletion.
- Verify cache invalidation and derived data after mutations across Dashboard, Workout, History, Progress, Program, and Profile.
- Run responsive and keyboard acceptance at 375px, a mid-width viewport, and desktop.
- Fix only defects caused by or directly blocking Wave 2 acceptance.
- Run the complete repository check and update Wave 2/status records when the gate passes.

## Out of scope
- Wave 3 authentication work, production deployment, unrelated refactors, or new product behavior.

## Acceptance criteria
- The critical Wave 2 browser journey passes from a clean isolated database.
- No Wave 2 page has horizontal page overflow at 375px, obscured fixed controls, broken focus order, or inaccessible destructive dialogs.
- Unit changes and deletions produce consistent derived data after reload.
- `npm run check` and the isolated browser suite pass.
- Every Wave 2 ticket is `done`, `WAVE2.md` reflects the gate result, and `STATUS.md` points to the next approved wave action.

## Verification
- `npm run check`.
- The repository's isolated browser/E2E command.
- Manual 375px, tablet, and desktop acceptance pass recorded in the ticket handoff.

## Stop conditions
- Stop and open a narrowly scoped follow-up if a failure is not a Wave 2 regression.
- Do not start Wave 3 or deploy production as part of this gate.

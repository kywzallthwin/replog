# W2-01: Persistent Workout-Level Notes

State: done

## Goal
Allow owners to save one optional note on an active workout and view it read-only after completion.

## Scope
- Add nullable `Session.notes` persistence and migration.
- Add a dedicated authenticated notes update endpoint.
- Trim notes, normalize blank input to `null`, and enforce 1,000 characters.
- Display an explicitly saved note editor on active workouts.
- Display non-empty notes read-only on completed workouts.
- Add server and client regression coverage.

## Out of scope
- Autosave, rich text, note history previews, and editing completed workouts.
- Previous-workout reference placement and other Wave 2 features.

## Acceptance criteria
- Active owners can set, replace, and clear notes.
- Session detail returns a string or `null` note.
- Unauthenticated, unauthorized, invalid, over-limit, and completed-session updates are rejected consistently.
- Save failures preserve the draft and expose an accessible error.
- The editor and display fit at 375px without horizontal overflow.

## Verification
- Focused server and client tests.
- `npm run check`.
- Manual 375px persistence, clearing, failure, and completed read-only checks.

## Stop conditions
- Do not expand into autosave, history previews, or concurrent mutation hardening beyond the existing active-session guard.

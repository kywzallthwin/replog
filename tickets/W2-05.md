# W2-05: Whole-Day Program Reordering

State: proposed

## Goal
Let an owner reorder complete days within a program while preserving each day's contents.

## Scope
- Add an authenticated program-day reorder endpoint with validated source and target positions.
- Renumber day order transactionally without changing day IDs, names, colors, or exercises.
- Add touch, pointer, and keyboard reordering to the program editor.
- Optimistically update the visible order and restore it with an accessible error if persistence fails.
- Ensure dashboard day suggestion and program views consume the new canonical order.

## Out of scope
- Moving exercises between days, copying days, or reordering historical sessions.
- Scheduling rules beyond the existing next-day behavior.

## Acceptance criteria
- Owners can move a day to any valid position and the order survives refresh.
- Existing day contents and IDs are unchanged.
- The dashboard's sequence follows the reordered program.
- Unauthenticated, unauthorized, invalid, and cross-program requests are rejected consistently.
- Touch and keyboard interactions remain usable at 375px.

## Verification
- Focused program API, editor, and dashboard regression tests.
- `npm run check`.
- Manual 375px touch and keyboard reorder, refresh, and failure rollback checks.

## Stop conditions
- Do not add cross-program moves, day duplication, or calendar scheduling.

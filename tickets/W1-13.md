# W1-13: API Readiness Retries

**State:** done

## Goal
Detect API availability after a Render cold start before a later integration enables authentication requests.

## Scope
- Add a reusable `/health` readiness probe.
- Add bounded retries, request timeout, and abortable retry delays.
- Support starting a fresh readiness attempt for manual retry.
- Add focused client unit tests.

## Out of scope
- Startup UI or authentication integration.
- Backend endpoint, authentication, CORS, cookie, or deployment changes.

## Acceptance criteria
- The existing `/health` endpoint is resolved from relative and configured API bases.
- Network, 5xx, timeout, and invalid-payload failures retry within a fixed attempt limit.
- In-flight requests and retry delays honor `AbortSignal`.
- A new call can be used for manual retry after failure.

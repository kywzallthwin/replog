# W1-12: Secure Cross-Origin Authentication

**State:** done

## Goal
Allow a separately hosted frontend to authenticate securely against the Express API using the configured frontend origin.

## Scope
- Treat `CLIENT_URL` as the canonical frontend origin for CORS, expected-origin checks, and redirects.
- Allow credentialed requests only from `CLIENT_URL` and existing safe development origins.
- Support cross-origin production authentication with secure, HTTP-only cookies and appropriate SameSite behavior.
- Keep cookie creation and clearing attributes identical.
- Preserve Google OAuth and password-reset redirects to `CLIENT_URL`.
- Add focused security and authentication tests.

## Out of scope
- Backend warming, UI changes, Render service separation, server startup changes, or deployment configuration.
- Wildcard credentialed CORS or weakening origin and CSRF validation.

## Acceptance criteria
- The configured frontend origin receives credentialed CORS headers; unconfigured origins do not.
- Allowed cross-origin production requests can use authentication cookies without disabling HTTP-only or Secure protections.
- Logout clears the authentication cookie with matching path, SameSite, and Secure attributes.
- State-changing requests continue to enforce expected-origin/Fetch Metadata protections.
- Google OAuth and password-reset redirects resolve from the canonical `CLIENT_URL`.
- Localhost and existing safe development-origin behavior remains supported.

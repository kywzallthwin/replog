# W2-14: Exercise Merge

State: in progress

## Active implementation
- Dedicated branch: `feat/w2-14-exercise-merge`.
- W2-13 is paused by explicit user direction; CF-05 remains paused.

## Goal
Let a user merge a built-in or owned custom source exercise into an owned custom keeper exercise.

## Scope
- Add the authenticated transactional merge API and server integration coverage.
- Move program-day and session references while preserving completed workout display names, set logs, and history grouping.
- Add the All Exercises merge flow with searchable custom keepers, confirmation, pending/error states, keyboard support, and query invalidation.

## Out of scope
- General exercise rename or deletion behavior from W2-06.
- Production database changes, deployment, or provider configuration.

## Acceptance criteria
- Source is built-in or caller-owned; target is caller-owned custom and differs from source.
- Unfinished-workout references reject with a conflict; inaccessible IDs return 404; invalid input or same IDs return 400.
- Program-day duplicates collapse at the keeper position and ordering remains compact.
- Completed SessionExercise rows move to the keeper without changing row IDs, snapshots, order, or SetLog rows.
- Custom sources are deleted only after all references are gone; built-in sources remain available.
- Client confirmation explains the merge effects and restores focus after success.

## Verification
- Focused server and client tests during implementation, then one complete `npm run check`.
- Manual 375px and keyboard review remains for the user.

## Stop conditions
- Do not deploy or apply production changes.
- Stop if unrelated ticket scope is required.

# W1-06: Correct Shell, Navigation, And Dashboard Mobile Issues

**State:** done

## Goal
Apply the confirmed baseline findings and approved dashboard decisions to the application shell, navigation, dashboard, and shared page-loading treatment.

## Scope
- Top/bottom navigation, shell, safe-area spacing, fixed navigation, overflow, and mobile scrolling.
- Dashboard Up Next states and active-program links.
- Branded loading for Dashboard, History, Progress, Program Library, Program Editor, Workout, and Profile primary page queries.

## Out of scope
- Program, workout, history, or progress features outside shared shell behavior.
- New dashboard rules, streak progress, timezone storage, weekday scheduling, or rest-day configuration.

## Acceptance criteria
- No unintended horizontal scrolling at 375px; fixed navigation does not cover interactive content.
- Active navigation and dashboard links are clear and keyboard usable.
- Loading, empty, error, and populated states follow the approved Up Next and loader decisions.
- Up Next selects the first or next non-empty ordered day, wraps correctly, remains unchanged across rest days, and shows Edit Program when all days are empty.
- Program links target `/program/:activeProgramId` when available and `/program` otherwise.
- Auth loading is full-screen; authenticated page-query loading preserves the shell, exposes a polite status, and is static with reduced motion.
- Mutation, dialog, and background-refresh pending states remain contextual.

## Verification
- Run focused client tests, lint, and typecheck.
- Manually check dashboard states, keyboard navigation, and reduced motion at 375px.

## Stop conditions

# CF-05: Production Cutover and Rollback

**State:** paused by explicit user sequencing override
**Operator:** Deployment agent or coordinator  
**Reviewers:** Security and deployment reviewers  
**Authorization:** Explicit user approval required

## Goal

Deploy the verified architecture without losing the Render fallback, test a genuine Render cold start, and enable steady-state security controls.

## Scope

Confirm account prerequisites; deploy compatibility Render and Cloudflare; move the custom hostname; verify auth/caching/cold-start/mobile behavior; enable API-only/edge enforcement; preserve rollback.

## Account Prerequisites

Confirm Cloudflare account/plan/usage, zone and hostname ownership, DNS target/TTL, stable validation origin, preview isolation, Render origin and Blueprint drift, rollback versions, production environment values, Google callbacks, Resend sender, Neon migration state, and Worker/Render logs.

## Deployment Sequence

1. Confirm CF-01–CF-04 are done and `npm run check` passes.
2. Complete security and deployment review.
3. Generate a strong shared `EDGE_PROXY_SECRET`; store it only in Cloudflare/Render secret stores.
4. Deploy Render compatibility mode with `SERVE_CLIENT=true`, `REQUIRE_EDGE_PROXY=false`, the secret, exact temporary origins, and current `CLIENT_URL`.
5. Run existing `migrate:deploy`; no new schema migration is expected.
6. Verify the Render frontend, `/health`, `/ready`, login, and one mutation.
7. Deploy the production Worker to its stable `workers.dev` hostname.
8. Add only that hostname to transitional origins and `PUBLIC_APP_ORIGINS`.
9. Validate assets, proxying, cookies, login/logout, caching, and errors.
10. Add the custom-domain callback URI to Google.
11. Attach the owned custom hostname to the Worker; coordinate any move from Render so it is not intentionally split.
12. Change Render `CLIENT_URL` to the Cloudflare custom origin.
13. Change `GOOGLE_CALLBACK_URL` to the Cloudflare `/api/auth/google/callback`.
14. Limit `PUBLIC_APP_ORIGINS` to custom and temporary validation origins.
15. Verify login, refresh, logout, OAuth, reset, a query, and a mutation.
16. Leave Render idle for more than 15 minutes.
17. Open a private browser and run cold-start acceptance.
18. Set `SERVE_CLIENT=false` and `REQUIRE_EDGE_PROXY=true`.
19. Confirm Render root has no second login page, direct API is blocked, and `/health` works.
20. Remove temporary origins and later disable the production `workers.dev` route.
21. Keep Render static code/build through rollback; remove it only in a later cleanup ticket.

## Production Smoke Tests

- React loads immediately and only RepLog UI appears while Render wakes.
- `/ready` returns controlled starting responses and eventually `{ "ok": true }`.
- Cold login, authenticated refresh, logout, failed credentials, optional OAuth, and reset links work.
- A stale query recovers and a representative mutation is sent once.
- `CF-Cache-Status` never reports cached API/auth/readiness; fingerprinted assets cache and SPA shell revalidates.
- Startup/login work at 375x667 and 375x900.
- Logs correlate by request ID and contain no cookies, credentials, OAuth codes, reset tokens, bodies, database URLs, or secrets.

## Rollback

1. Set `SERVE_CLIENT=true` and `REQUIRE_EDGE_PROXY=false`.
2. Restore previous `CLIENT_URL`, `GOOGLE_CALLBACK_URL`, DNS/domain attachment, and only needed transition origins.
3. Roll back Worker or Render deployment if configuration rollback is insufficient.
4. Do not rotate JWT/database credentials or roll back the database.
5. Repeat auth, health, readiness, query, and mutation smoke tests.

## Acceptance Criteria

- Cloudflare serves the SPA before Render wakes and only approved routes reach Render.
- Auth/OAuth/reset remain first-party with no third-party-cookie dependency.
- API/auth responses never cache; mutations never replay.
- Direct Render API is blocked while `/health` works.
- Rollback works without secret rotation.
- Reviews, mobile/cold-start acceptance, and `npm run check` pass.

## Stop Conditions

Stop if hostname/DNS is unclear, quota/account access is insufficient, Google callback cannot be authorized, Render differs unexpectedly, startup cannot be classified, cookies fail, a mutation duplicates, authenticated content caches, review findings remain, rollback fails, or authorization is absent.

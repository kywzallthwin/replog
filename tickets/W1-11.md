# W1-11: Configurable Production API URL

**State:** done

## Goal
Allow the Vite frontend to call a separately hosted Express API while preserving same-origin production fallback and local development behavior.

## Scope
- Make `VITE_API_URL` usable in production.
- Normalize trailing slashes and repeated terminal `/api` segments.
- Preserve `/api` as the production fallback when `VITE_API_URL` is absent.
- Preserve the browser hostname with port 4000 as the development fallback.
- Document that Vite variables are public browser-build values and must not contain secrets.
- Add focused tests for URL resolution and normalization.

## Out of scope
- Backend CORS, cookies, CSRF, redirects, or authentication behavior.
- Backend readiness probing and startup UI.
- Render service separation or deployment.

## Acceptance criteria
- A configured development or production URL resolves to exactly one terminal `/api` path.
- URLs with whitespace, trailing slashes, or an existing `/api` suffix normalize correctly.
- Production without configuration uses same-origin `/api`.
- Development without configuration uses the browser hostname on port 4000, with a localhost fallback outside the browser.
- No secret is added to a `VITE_*` variable.
- Focused automated tests cover every resolution mode.

## Verification
- Focused API URL tests pass.
- Client typecheck and lint pass.
- `git diff --check` passes.

## Stop conditions
- Stop if completing this ticket requires server authentication/security changes, readiness UI, or Render deployment configuration.
- Stop if unrelated working-tree changes cannot be isolated from this ticket's commit.

# W2-16: Log Past Workout

State: active

## Goal
Add historical manual workout logging through the existing session and workout editor flows while preserving live workout behavior.

## Scope
- Add History entry, manual workout setup, program-day selection, blank workout creation, draft resume/discard, and historical date selection.
- Adapt the shared workout page/editor to distinguish persisted LIVE and MANUAL sessions; reuse exercise cards, set editing, exercise selection/swap, saved-set operations, and existing APIs where possible.
- Extend Session persistence and APIs with source, calendar workout date, and notes; enforce ownership, draft uniqueness, live/manual coexistence, and completed-session immutability.
- Complete manual sessions atomically and idempotently, include them in history and existing workout/set/volume/progress statistics, and keep drafts out of history/statistics/live active-workout behavior.
- Add the required database migration without applying it to production.
- Preserve existing live start/resume, timers, cancellation, completion, and read-only history detail behavior.

## Out of scope
- Cloudflare, Render, DNS, OAuth, production secrets/configuration, deployment, and migration application to production.
- Commit, push, or deployment.
- Unrelated W2-15 Program Editor changes or later-wave work.

## Acceptance criteria
- History exposes a compact “+ Log Workout” entry; `/history/log` offers a compact native date-picker row, From Program, Blank Workout, and a conditional Resume draft. The entire 56px-minimum date row is one clickable/focusable native control with 16px horizontal padding and whole-row hover, pressed, and focus feedback; Change is visual guidance only. The row shows a local-calendar formatted date, preserves `YYYY-MM-DD` URL state, and blocks new draft creation for malformed, empty, or future dates.
- Resume draft appears as one white rounded card with a flexible navy resume link and independent 44px trash button; it has no chevron and uses the same card shadow lift and visible focus ring as From Program. The trash icon is muted at rest and turns red on hover/focus. The button opens an alert dialog titled “Discard draft?” with the message “This will delete your manually entered workout and sets.” and actions “Keep draft” and “Discard draft.” Keep draft receives initial focus. The dialog deletes only the queried manual draft through the existing session-cancel API, removes its session cache and invalidates the manual-draft cache, then returns focus to From Program. Cancel/Escape restore focus to the trash button. Pending deletion blocks duplicate submission and dismissal; failures stay in the dialog with retry.
- From Program is the primary setup action; Blank Workout is a smaller, visually secondary clickable row. From Program opens a responsive inset modal at Choose Program (not a bottom sheet); selecting a program changes the same modal to Choose Workout. The active program appears first, remaining programs retain API order, zero-day programs are excluded, and workout days retain stored day order. The selected date remains unchanged. Popup steps use local state; browser Back retains normal page navigation and refresh returns to setup with the modal closed.
- Program cards show stored names, day counts, a subtle Active badge beside the count, and one right-aligned chevron. Names use two-line ellipsis with unbroken-word wrapping. The modal fetches program summaries with `dayCount` and only fetches details for the selected program using the existing query keys. Loading/errors have retry states; empty or unavailable selected programs can return to Choose Program. Program/day names preserve stored spelling and capitalization and avoid horizontal overflow at 375px.
- Both picker lists use the same white, slate-bordered rounded card treatment on a light slate scrolling surface, with a flexible two-line name area and fixed right chevron. Program cards show count and Active metadata; workout cards show only their day name. Rows keep minimum heights of approximately 76px and 64px respectively and provide hover, pressed, focus, and disabled feedback. The selected-program back row remains visually quieter on white and retains its directional arrow.
- The inset modal reuses `Dialog` focus trapping, pre-paint reference-counted scroll locking, Escape handling, and focus restoration to From Program. It is centered at about 480px on desktop, uses a stable `min(640px, 85dvh)` height capped by the overlay’s available safe-area height, and keeps header/footer fixed while the list scrolls internally. It has 44px controls, approximately 76px program cards, and 64px workout rows. Choose Workout shows the selected program name and conditional Active badge as a plain muted label above the workout cards without a background strip. Choose Program has a full-width Cancel footer; Choose Workout has equal-width Back and Cancel actions, with no header arrow controls. Step changes reset list scroll; headings receive prevent-scroll focus when entering a step, while returning to programs focuses and reveals the selected card within the list if needed. Back navigation, Cancel, Escape dismissal, and selection are disabled during draft creation; merely opening the modal or choosing a program creates no draft.
- Manual entry uses the shared workout editor and persisted session structure. From Program snapshots the selected day; Blank Workout starts empty. Manual mode excludes all live and rest timers/indicators and rest-state writes.
- Manual metadata supports a date no later than the user’s local today, blank or whole-minute duration from 1–1,440, and notes up to 2,000 characters. Date, duration, and note autosave on blur and flush before navigation or save; failures remain visible and retryable.
- Manual drafts survive refresh and remain outside History/statistics. Discard requires confirmation. Save requires at least one saved set, completes atomically and idempotently, then returns to History.
- Completed manual workouts appear with a subtle “Manually logged” label and use the existing read-only detail view. Calendar date governs display, ordering, grouping, progress labels, and previous-workout comparisons without timezone shifts.
- One manual draft can coexist with one live session. Manual drafts do not appear as dashboard active workouts or cause live-session/program-activation conflicts. Exercise reference protections apply to either draft type.
- API responses expose source, workoutDate, and notes; history includes manual fields and exercise-name preview. Completion invalidates session, history, dashboard, and progress caches.
- At 375px, both shared set adders and entry flows have 44px touch targets, no horizontal overflow, and preserve focus/keyboard behavior.

# W1-07: Correct Program And Exercise-Picker Mobile Issues

**State:** review

## Goal
Fix confirmed mobile and accessibility issues in program browsing, editing, menus, dialogs, and exercise selection.

## Scope
- Program library/editor, action menus, delete dialogs, exercise picker, custom-exercise form, long names, empty states, scrolling, and touch targets.
- Shared dialog focus, Escape, background-scroll, and focus-restore behavior.
- Preserve exercise reordering and the two-step custom-exercise flow: save returns to the picker with the exercise selected, then Add Exercise confirms.

## Out of scope
- Whole-day reordering, custom-exercise edit/delete, program API changes, and workout-specific picker acceptance.

## Acceptance criteria
- Program screens work at 375px without clipping or horizontal scrolling.
- Menus/dialogs contain Tab and Shift+Tab, dismiss safely, and restore focus to a surviving trigger or stable fallback.
- Empty, loading, error, and long-name states remain understandable; primary names wrap at mobile widths.
- Existing program, day, exercise, template, copy, activation, deletion, and custom-exercise creation behavior remains intact; copied names stay within 80 characters.
- Standalone changed actions are at least 44px by 44px; constrained dialogs scroll internally while background scrolling is locked.
- Picker states distinguish empty sources from no-match searches, preserve grouping, identify added exercises, and retain a saved custom exercise selection.
- Pending mutations prevent conflicting changes and provide safe conflict, failure, retry, and reorder feedback.

## Verification
- Run focused client tests, lint, and typecheck.
- Manually check program and picker flows at exactly 375x900 and 375x667.
- Test keyboard/Escape behavior, scrolling, focus fallback, long names, pending states, and failed mutations.

## Stop conditions

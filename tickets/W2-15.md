# W2-15: Program Editor Page

State: active

## Goal
Update `/program/:programId` to present clear program details and consolidate program actions while preserving the existing workout-day editor.

## Scope
- Refine the editor header with the RepLog logo, primary navigation, Edit Program title, Programs return link, program name, active badge, and exercise count.
- Add a responsive row for Add Day, inactive-program activation, and the anchored program options menu.
- Add an inactive-only action-row activation button, plus menu actions for rename, duplicate, and delete using existing APIs, safeguards, and dialog patterns.
- Add focused client coverage for editor header, menu, action row, mutation flows, focus handling, and existing day editing/reordering behavior.

## Out of scope
- Route, server API, database schema, authentication, or deployment changes.
- Changes to program-list behavior beyond reusing its existing API and dialog patterns.
- Changes to day editing, exercise removal, and exercise ordering behavior.

## Acceptance criteria
- The editor shows “Edit Program,” a “← Programs” link to `/program` that preserves focus on the Programs heading, the program name clamped to two lines, an Active badge only for active programs, and the exercise count derived from program days.
- The action row order is “+ Add Day” → “Make active” → compact options trigger for inactive programs, and “+ Add Day” → options trigger for active programs. Add Day flexes while the other controls retain their natural widths; the inactive row stays on one line at 375px, and controls wrap cleanly at narrower widths. Every control has at least a 44px touch target.
- The options menu remains an anchored popover with viewport positioning, outside-click dismissal, Escape handling, and keyboard navigation.
- Inactive programs can be activated from the action row through the existing activation mutation and active-workout safeguard, with “Activating…” shown while pending; the options menu does not contain activation. Rename refreshes the editor heading; duplicate confirms a copied name before creating and navigating to the new editor; delete reuses confirmation and remains disabled for the active program.
- Menu actions close the menu and dialogs restore focus sensibly. Existing day editing, exercise removal, and reordering continue to work.
- Program navigation remains selected on both `/program` and `/program/:programId`.

## Verification
- Focused client tests cover header and return focus, two-line long names, active/inactive action-row and menu options, Add Day layout and behavior, activation pending/conflict/success, rename, duplicate, deletion, popover dismissal, keyboard focus, and day editing. Run the full client suite to check for regressions in exercise reordering.
- Manual 375px and narrower-width review covers the inactive and active action rows, long names, popover near viewport edges, touch targets, bottom navigation, and horizontal overflow.
- Run focused client tests, client lint, client typecheck, the full ticket check once, and `git diff --check` before review.

## Stop conditions
- Do not change routes, server APIs, database schema, or production configuration.
- Stop if preserving the existing day editor requires unrelated behavior changes.
- Preserve pre-existing worktree changes.

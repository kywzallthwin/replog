# W2-10: Estimated 1RM Guide Route

State: proposed

## Goal
Explain how RepLog chooses estimated-1RM personal bests through a focused, mobile-friendly `/guide` page.

## Dependencies
- W2-08 establishes unit terminology and formatting used in examples.
- W2-09 establishes the Progress presentation that links to the explanation.

## Scope
- Add an authenticated `/guide` route using the existing protected page shell and navigation patterns.
- Publish the estimated 1RM formula, worked comparison, eligible workout/set rules, and distinction from raw heaviest set from `TODO.md`.
- Add a contextual "How this works" link from the Progress personal-best area and a clear route back.
- Use semantic headings, readable formula markup, and unit-aware examples where practical.
- Remove the completed first-guide TODO while leaving future guide topics deferred.

## Out of scope
- A documentation CMS, search, multiple guide articles, calculators, or the deferred Heaviest Set, Progress Trend, Set Types, Total Volume, and Workout History sections.

## Acceptance criteria
- Authenticated users can reach `/guide` from Progress and return without losing their selected exercise context.
- The page states the formula `weight x (1 + reps / 30)` and explains that only normal sets from finished workouts count.
- The comparison makes clear why a lighter multi-rep set can outrank a heavier single.
- Headings, formula, links, and examples are accessible and fit at 375px without overflow.
- Unauthenticated access follows the existing protected-route behavior.

## Verification
- Focused route, navigation, content, and auth-boundary tests.
- `npm run check`.
- Manual 375px and desktop navigation/readability checks.

## Stop conditions
- Do not build the deferred guide sections or introduce authoring infrastructure.

# W2-08: Kg/Lb Preference And Conversion

State: proposed

## Goal
Let each user choose kilograms or pounds for display and entry while keeping kilograms as the only canonical stored unit.

## Scope
- Add a user weight-unit preference with `KG` as the migration default and expose it through authenticated user payloads.
- Add a focused preference update contract and kg/lb control in Profile.
- Centralize weight, estimated 1RM, progress delta, and volume formatting/conversion in shared client helpers.
- Apply the preference to active set entry/editing, previous references, completed workouts, History, Dashboard/Profile stats, and Progress.
- Convert pound inputs to kilograms only at the API boundary; keep all database fields and server calculations in kilograms.
- Use the exact conversion `1 kg = 2.2046226218 lb`, display at most one decimal place, and avoid cumulative round-trip conversion.

## Out of scope
- Per-exercise units, plate calculators, body-weight tracking, locale-specific unit defaults, or converting stored rows.
- Changing API field names such as `weightKg`.

## Acceptance criteria
- A user's selection persists across devices and new sessions.
- Switching units updates every user-visible weight label without changing stored values or calculated rankings.
- Pound set entry is converted once to kilograms and displays the expected pound value when revisited within normal rounding tolerance.
- Existing users default to kilograms and another user's preference is unaffected.
- Unit controls and numeric inputs remain accessible and fit at 375px.

## Verification
- Focused server preference tests and client conversion/rounding tests.
- Cross-page regression tests for workout, history, dashboard, profile, and progress.
- Migration validation and `npm run check`.
- Manual 375px kg-to-lb switch, pound entry/edit, refresh, and cross-page consistency checks.

## Risks And Rollback
- Risk: inconsistent one-off conversions can produce contradictory displays or round-trip drift. Require shared helpers and canonical kg API values.
- Rollback: retain the additive preference column with the default `KG`; UI conversion can be disabled without rewriting workout data.
- Independent review is required for the migration and conversion boundary before `done`.

## Stop conditions
- Do not rename canonical kg fields, rewrite stored weights, or add unrelated measurement preferences.

# CF-00: Cloudflare Frontend and Render API Migration

**State:** proposed

## Goal

Move React to Cloudflare Workers Static Assets with a narrowly scoped Worker proxy, while keeping Express on the sleeping Render Free Web Service and PostgreSQL on Neon. This file is the migration index and shared contract; implementation is divided so no agent owns the whole feature.

## Target Architecture

```text
Browser
  | HTTPS: SPA routes, /api/*, /ready
  v
Cloudflare Worker + Static Assets
  |-- static/SPA route ----------> React assets/index.html
  `-- /api, /api/*, /ready -----> Render Express ----> Neon
```

Startup: Cloudflare serves React immediately; `ApiStartupGate` shows `Starting RepLog...`; same-origin `/ready` wakes Render and verifies Neon; only `{ "ok": true }` mounts the router. Render HTML and edge failures never replace the SPA.

Browser API requests remain relative `/api`. `/health` remains direct Render liveness. Cookies remain host-only, HTTP-only, `Secure`, `SameSite=Lax`, and retain their paths. Do not add `Domain` or `SameSite=None`. Google OAuth returns through Cloudflare `/api/auth/google/callback`; password-reset links use the Cloudflare public origin.

## Shared Proxy Contract

Only exact `/api`, `/api/*`, and exact `/ready` are proxied. All other paths resolve as assets, SPA routes, or controlled `404` responses. Callers never select the upstream.

| Condition | Result |
|---|---|
| `/ready` exceeds 12 seconds | `504` edge error |
| `/api` exceeds 30 seconds | `504` edge error |
| Upstream network failure | `502` edge error |
| HTML on a proxy route | `503` JSON |
| Invalid readiness JSON | `503` JSON |
| Valid upstream response | Preserve status, body, cookies, redirect |

Readiness failure:

```json
{ "ok": false, "code": "API_STARTING" }
```

Edge API failure:

```json
{
  "error": "The RepLog service is temporarily unavailable",
  "code": "UPSTREAM_UNAVAILABLE",
  "retryable": true
}
```

Readiness failures include `Retry-After: 5` and `Cache-Control: no-store`.

### Header policy

- Strip `Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailer`, `Transfer-Encoding`, and `Upgrade`.
- Strip incoming `Host`, forwarding identity, client IP, edge-secret, and internal request-ID headers before adding trusted values.
- Preserve browser `Origin`; use `redirect: "manual"`; preserve multiple `Set-Cookie` headers separately.
- Never trust browser-provided `X-Forwarded-For` or `CF-Connecting-IP`.
- Trust Cloudflare client IP only with a valid shared edge secret.
- Propagate a sanitized request ID derived from `CF-Ray`.
- Never cache proxy responses; preserve normal static-asset caching.

## Locked Decisions

- Use Workers Static Assets, SPA fallback, and `run_worker_first` only for approved routes.
- Keep production `VITE_API_URL` unset and the Render Blueprint as one service.
- Keep Express `trust proxy` at one Render hop.
- Keep Render static serving behind `SERVE_CLIENT` during rollback; remove it later in a separate cleanup ticket.
- Keep previews static-only and isolated from production data.
- Never replay a dispatched non-idempotent request.
- Preserve JWT and Neon credentials.
- Prefer an owned custom hostname; `*.onrender.com` remains the upstream API hostname.

## Agent Workflow

- **Coordinator:** activates tickets, protects contracts, integrates, runs final checks, updates handoff.
- **Implementer:** edits only active-ticket files and runs focused checks.
- **Reviewer:** independently reviews without editing.
- **Verifier:** runs ticket checks and reports evidence.

For each ticket: make it the sole active ticket; read `AGENTS.md`, `STATUS.md`, and that ticket; edit only owned files; run focused checks; obtain review; resolve findings; run `npm run check`; record evidence. No agent commits, pushes, deploys, or changes accounts without explicit authorization.

## Final Acceptance

- CF-01 through CF-04 pass focused and full verification.
- CF-05 passes authorized production acceptance.
- A true cold start shows only RepLog UI.
- Auth, optional OAuth, reset, caching, and mutation-safety checks pass.
- Direct Render API access is blocked in steady state while `/health` works.

## Out of Scope

Database/provider changes, JWT changes or rotation, cross-site cookies, wildcard CORS, mutation replay, Render upgrades, unrelated features, early removal of Render static serving, and unauthorized production/account changes.
